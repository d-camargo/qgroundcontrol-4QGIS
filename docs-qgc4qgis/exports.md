# Mission export options

In addition to QGroundControl's native `.plan` format, QGC4QGIS allows exporting photogrammetric flight plans to **Litchi** (`.csv` and `.kml` formats) and **DJI Fly** (WPML `.kmz` format) applications.

## Supported formats overview

| Format | File Extension | Target Applications | Terrain Mode Support | Key Features & Constraints |
| :--- | :--- | :--- | :--- | :--- |
| **QGroundControl Plan** | `.plan` | QGroundControl, PX4, ArduPilot | Full native terrain following | Complete mission structure with camera triggers and telemetry parameters. |
| **WPML Package** | `.kmz` | DJI Fly, Litchi Hub 2 | Converted to relative altitude above takeoff | Native DJI WPML format containing `template.kml` and `waylines.wpml`. |
| **Litchi Mission** | `.csv` | Litchi (Classic Hub & Hub 2), Litchi Mobile | Relative altitude | Standard D8 CSV table including waypoint coordinates, altitude, heading, and gimbal pitch. |
| **Litchi KML** | `.kml` | Litchi Classic Hub | Relative altitude | Simple KML placemarks with waypoint coordinates and altitudes; requires photo action setting on import. |

---

## Native QGroundControl (`.plan`) export

The native `.plan` format exports complete mission definitions for QGroundControl:

- Contains survey complex items (`SurveyComplexItem`), transects, turnarounds, speed settings, camera specs, and autopilot firmware targets (PX4 or ArduPilot).
- Preserves original terrain-following parameters when Copernicus DEM or local elevation rasters are used.
- Ready to be loaded directly into QGroundControl on desktop or mobile devices.

## WPML (`.kmz`) export for DJI Fly and Litchi Hub 2

The WPML `.kmz` format is the official DJI format for wayline mission execution on newer DJI aircraft.

### Terrain mode conversion

- Terrain-following missions are converted into altitudes relative to the takeoff point (`PONTO_DECOLAGEM` parameter, which defaults to the elevation of the first waypoint).
- This allows aircraft using WPML to follow terrain profiles even when operating with relative height commands.

!!! warning "Warning: Relative height $\le 0$"
    The plugin issues a warning if any calculated relative height is $\le 0$ meters above the takeoff point.

### Loading in DJI Fly

1. In the **DJI Fly** app (or on the DJI RC / RC 2 / RC Pro remote controller), create and save a test mission with **1 waypoint** so that the app generates its file structure and a unique folder identifier (GUID).
2. Locate the created GUID folder in device storage:
   - **Android**: `Android/data/dji.go.v5/files/waypoint`
   - **iOS / Controller Storage**: `Files/DJI Fly/wayline_mission/`
3. Rename the exported `.kmz` file to match the folder's GUID name.
4. Replace the original `.kmz` file inside the GUID folder with the renamed file generated by QGC4QGIS.

!!! warning "Do not re-edit inside DJI Fly"
    Do not edit or save the imported mission inside the DJI Fly app! If the mission is saved in DJI Fly, the app rewrites the WPML structure, which can corrupt or remove photo triggers and custom waypoint actions.

### Loading in Litchi Hub 2

- The same WPML `.kmz` file exported for DJI Fly can be imported directly into [Litchi Hub 2](https://hub.flylitchi.com) as a mission file.
- Hub 2 detects the `template.kml` and `waylines.wpml` components inside the compressed archive.

!!! warning "Import dialog in Hub 2"
    Hub 2 has two separate import dialogs. The area/overlay dialog (`.kml`, `.kmz`, `.geojson`, `.json`) only draws visual map layers and **does not create flight waypoints**. To load the flight route, always use the mission import dialog (**Mission → Import**).

## Litchi (`.csv`) export

The `.csv` format exports flight routes formatted for Litchi (D8 specification).

### Required manual global settings in Litchi Hub

When importing a `.csv` mission into the Litchi Mission Hub ([flylitchi.com/hub](https://flylitchi.com/hub) or [hub.flylitchi.com](https://hub.flylitchi.com)), three global parameters must be configured manually before saving:

1. **Heading Mode**: Select **"Custom (WP)"** so the application uses the `heading(deg)` column recorded in the CSV (the calculated azimuth for each flight strip).
2. **Finish Action**: Set the desired end-of-mission behavior (e.g., *Return to Home (RTH)*, *None*, or *Land*).
3. **Path Mode**: Select **"Straight Lines"** — the CSV is generated with `curvesize=0` and does not define curved turns.

!!! warning "Trigger mode and photo action warning"
    When exporting to `.csv`, if the selected photo trigger mode does not generate explicit waypoint photo actions (for example, when using distance-based or time-based triggers without waypoint sampling), Litchi will not perform photo triggers per waypoint. To guarantee waypoint sampling with photo triggers, generate the mission with **Trigger Mode = "By photo"**.

## Litchi KML (`.kml`) export for Classic Hub

The `.kml` format is designed specifically for the Classic Litchi Mission Hub ([flylitchi.com/hub](https://flylitchi.com/hub)).

### Loading steps

1. Open the [Classic Litchi Mission Hub](https://flylitchi.com/hub).
2. Click **Mission → Import** and select the `.kml` file.
3. Check **"Add take photo action"** and leave **"Placemarks as POI" unchecked**.
4. This configuration automatically adds a *Take Photo* action at **every** waypoint and forces the path mode to *Straight Lines*.

### Trigger mode requirement

- Using `.kml` format requires the mission to be generated with **Trigger Mode = "By photo"**. Otherwise, the KML vertices will only represent the entry and exit endpoints of each transect line.
- Setting **Trigger Mode = "By photo"** also ensures proper waypoint sampling when exporting to `.csv`.

### Missing parameters in KML

Because KML files contain only geographic coordinates and altitudes, non-positional parameters are not imported and must be configured manually in the Mission Hub:

| Parameter Missing from KML | Default Classic Hub Behavior | Hub Adjustment Location |
| :--- | :--- | :--- |
| **Heading** | Direction to next waypoint (or North) | Mission Settings Panel (`Heading Mode`) |
| **Gimbal Pitch** | $0^\circ$ (horizontal) | Waypoint Properties / Actions |
| **Speed** | Global mission default speed | Mission Settings Panel (`Speed`) |
| **Path Mode (Curved/Straight)** | *Straight Lines* (forced by *Take Photo*) | Mission Settings Panel (`Path Mode`) |
| **Points of Interest (POI)** | Not imported (keep "Placemarks as POI" unchecked) | Add manually on map |
| **Explicit Altitude Mode** | Relative to takeoff location ground (*Relative*) | Individual waypoint properties |

### Classic Hub KML importer behavior and limits

- **Silent Altitude Adjustments**: The Classic Hub KML importer silently converts any height of **0 m to 30 m**, and truncates altitudes outside `[-200, 500]` meters. The plugin displays warnings prior to export when these conditions occur.
- **Waypoint Ceiling**: The Classic Hub KML importer supports up to **10,000** waypoints (excess waypoints beyond 10,000 silently vanish without error warnings).
- **Incompatibility with `.kmz`**: The **Classic Hub does not support `.kmz` files**. Do not import `waylines.wpml` files into the Classic Hub, as WPML coordinates lack altitude definitions and will cause all mission heights to default to 30 m.

## Application limitations and behaviors

### Waypoint limits

- **Litchi**: Maximum limit of **99 waypoints** per mission. QGC4QGIS alerts the user when a mission exceeds 99 waypoints.
- **DJI Fly**: DJI does not publish an official hard limit, but the accepted community limit is **200 waypoints**. QGC4QGIS issues a warning when a mission exceeds 200 waypoints.

### Hub comparison matrix

| Interface | URL | Supported Mission Import Formats | Note |
| :--- | :--- | :--- | :--- |
| **Classic Hub** | [flylitchi.com/hub](https://flylitchi.com/hub) | `.csv`, `.kml`, `.wpml` | Requires "Add take photo action" for KML. |
| **Hub 2** | [hub.flylitchi.com](https://hub.flylitchi.com) | `.csv`, `.kmz` (WPML) | Use mission import dialog, not area/overlay dialog. |
